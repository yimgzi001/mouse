# 手势调整记录（2026-11-17）

用户试用[识别修复](recognition-fixes-2026-11-17.md)后反馈没有大问题，但右手五指唤出选窗偏慢、唤出后选窗移动偏快，并决定取消四指快切、把右手两指改为滚动、拖拽换到右手三指。本轮据此调整。下列结果来自自动化测试和对运行日志的分析，新行为尚未经真人试用。当前操作以[项目使用说明](../README.md)为准，配置约束见[当前架构与配置](architecture.md)。

## 五指唤出慢的原因

试用期间 `-verbose` 运行日志里，右手有 9 次张手唤出了选窗，从张开到唤出用了 0.4～1.3 秒，中位约 0.7 秒；另有两次张手 4.3 秒和 3.2 秒始终没有唤出。自然张开的右手，拇指开合度只有 0.3～0.5，达不到手指算“张开”的 0.6，手先被认成四指；等拇指读数越过门槛变成五指，又要按“从其他手势换成五指”再等 300ms。

## 行为变化

| 项目 | 之前 | 现在 |
|---|---|---|
| 张开手掌时的拇指 | 与其他手指一样，开合度高于 0.6 算张开、低于 0.4 算收起 | 其余四指张开时，高于 0.25 算张开、低于 0.15 才算收起；其他手型不变 |
| 五指从其他手势切换 | 至少 300ms | 至少 200ms |
| 五指确认期间的手部移动 | 不看 | 掌心移动超过 0.3 掌长则重新计时，手停住才唤出；唤出以后移动不受影响 |
| 选窗步距 | 切屏倍率 1 时每 0.45 掌长换一个窗口 | 0.6 掌长；用户当前倍率 1.69 下由约 0.27 掌长变为约 0.36 掌长，慢约三分之一 |
| 四指快挥快切 | 右手四指左右挥，Alt＋Tab / Alt＋Shift＋Tab | 取消。四指仍被识别但没有绑定，只表示松开上一个手势；切回上一个窗口用张手后直接握拳 |
| 右手两指 | 拖拽 | 上下滚动 |
| 右手三指 | 滚动 | 拖拽 |
| 左手三指 | 滚动 | 不变 |
| 切屏倍率 | 同时决定选窗步距和快挥阈值 | 只决定选窗步距；快挥固定为 250ms 内 0.65 掌长 |

用户配置里的 `fiveConfirmMs`（当前 150ms）和切屏倍率没有改。按这些门槛估算，手张开并停住后约 0.3 秒唤出，这个数字没有实测。拇指明显收进掌心仍是四指，不唤出：日志里有 5 段做得较松的后三指（食指半伸、拇指开合度 0～0.18），若完全不看拇指会被当成五指。

捏合当主要左键的方案没有采用：用户试过，捏合时食指会动、光标跟着移，点不到想点的位置。捏合保持为备用左键。

## 配置升级

配置版本由 3 升为 4。读取版本 3 时自动升级：删除默认的四指快切绑定；“页面滚动”（任意手三指）和“右手两指拖拽”都还是默认手势、且目标手势没被其他绑定占用时，换成“右手两指滚动”“左手三指滚动”和“右手三指拖拽”，等待时间等参数保留；改过的绑定保持原样。倍率、识别设置和手势列表不变。新程序启动时即写回版本 4，原文件备份为 `settings.json.v3.bak`，已有备份不覆盖。

旧程序读不了版本 4 配置。回退时先退出新程序，再把 `settings.json.v3.bak` 复制回 `settings.json`。

本轮同时修正了读取配置的一处问题：绑定列表原先解码到默认预设之上，同一位置默认绑定的动作参数会混进文件里的绑定，列表顺序与默认不同时会因“未知动作参数”读取失败。现在列表完全以文件为准。

## 尚未确认

- 真人试用：五指唤出是否够快；自然放松的拇指是否都能算五指；放宽拇指门槛后，后三指或其他手势松开时是否会误唤出选窗；“手停住才唤出”是否反而妨碍边移动边张手的习惯。
- 选窗放慢三分之一是否合适；不合适可调切屏倍率。
- 右手两指滚动与一指移动之间切换时是否会误滚动；右手三指拖拽是否顺手。
- 取消快挥后，“张手后直接握拳”能否替代原来的快切。
