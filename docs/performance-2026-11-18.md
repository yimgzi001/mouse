# 性能检查记录（2026-11-18）

> 接续[2026-11-17 性能检查记录](performance-2026-11-17.md)。本轮按用户要求降低 CPU 与内存占用；当前实现与待验收事项见[文档入口](README.md)。

结论：CPU 大头仍是 ONNX 推理，其中掌心检测（找手）单次最贵；Go 侧每帧只分配约 1.2 KB，测量期间不触发垃圾回收。本轮两处修改：

1. ONNX Runtime 不再使用每轮内存计划，张量从内存池逐个分配，模型权重放在池外。图片回放进程跑完三个场景后的私有内存从 83～100 MB 稳定到约 82 MB，推理速度不变。
2. 找手间隔（用户选定的均衡方案）：跟踪单手时找第二只手 66→100ms，画面里没有手时 120→200ms。新举起的手最多多等 34ms 或 80ms 才被跟踪；已跟踪的手和双手不受影响。

没有降帧率、分辨率或线程数，没有更换或量化模型，没有修改手势阈值。

## 环境与口径

- 同一台机器（AMD Ryzen 7 5700U，8 核 / 16 逻辑处理器），ONNX Runtime 1.23.2，Go 1.27.2。
- 整机 CPU 按 `100 × CPU秒增量 / 实际秒增量 / 16` 计算；括号里的「单核」是同一数值乘 16，便于看清大小。
- 测量时手势鼠标第 4 版和用户的其他程序仍在运行，单轮 CPU 波动大：同一配置的掌心检测出现过 11ms 到 35ms。下文只采用相邻交替的轮次和同一进程内交替计时，并注明受干扰的轮次。
- `cmd/perfcheck` 本轮增加了工作集、私有内存、Go 堆、每帧分配量、垃圾回收次数和每帧缺页数，以及 `-detect`、`-idle` 找手间隔和 `-cpuprofile`。场景与图片同上一轮记录。

## 修改前的实时程序

对正在运行的第 4 版进程采样：

| 采样 | 整机 CPU | 工作集 MB | 私有内存 MB | 线程 | 句柄 |
|---|---:|---:|---:|---:|---:|
| 20 秒，大部分时间有一只手 | 4.45%（单核 71%） | 106.2 | 95.3 | 25 | 650 |
| 12 秒，没有手 | 2.5%（单核 41%） | | | | |

没有手时按线程统计，推理的两个线程合计约单核 28%，其余线程（摄像头格式转换、界面、Go 运行时）合计约单核 13%。默认配置没有「手势暂停/恢复」绑定，暂停时不跑识别，只剩摄像头采集。

## 图片回放：修改前后

每场景 300 帧，按 30 FPS 节奏，修改前后两个程序交替各跑两轮。

| 场景 | 修改前整机 CPU | 修改后整机 CPU | 掌心检测次数（前→后） |
|---|---:|---:|---:|
| 无手 | 1.02%、1.09%（单核 16～18%） | 0.66%、0.70%（单核 11%） | 75 → 46～47 |
| 单手 | 4.13%、4.84%（单核 66～78%） | 4.00%（单核 64%）；受干扰轮 4.26% | 140～141 → 83～86 |
| 双手 | 5.30%、5.62%（单核 85～90%） | 5.83%（单核 93%）；受干扰轮 6.46% | 0 → 0 |

无手场景的下降与「每次掌心检测约占 20ms CPU」的估算一致。单手场景每 10 秒少约 55 次检测，估算少约 11 个单核百分点，但本机单轮波动约 ±8 个点，实测只能确认方向。双手稳定跟踪时不跑掌心检测，间隔修改不影响它；内存设置的速度影响见下一节的同进程计时。各场景实际速率均为 30.00 FPS。

更多间隔的单独采样（单核）：找第二只手 100ms 时单手 57%、133ms 时 55%；空画面 200ms 时 11%、250ms 时 9%；200ms/300ms 组合时单手 50%、无手 9%，但新手最多多等 134ms/180ms，用户选择了 100ms/200ms。

## 内存

ONNX Runtime 加载两个模型后就占约 68～70 MB 私有内存；Go 堆只有 3～5 MB。原来的每轮内存计划把一次推理的所有中间张量合成一大块向内存池申请，内存池按 2 的幂取整，有时还会多加一块，所以同样的运行有时停在 83 MB，有时停在 100 MB。

| 配置 | 加载后私有 MB | 三个场景后私有 MB | 双手每帧缺页 | 掌心检测中位 ms | 关键点中位 ms |
|---|---:|---:|---:|---:|---:|
| 原默认 | 68～70 | 83～100（六轮） | 0.1 | 10.98 | 7.28 |
| 现默认：逐个分配 + 权重在池外 | 61.7 | 81.6～82.3 | 0.1 | 11.00 | 7.25 |
| 关掉内存池（未采用） | 61～63 | 67～69 | 约 2300 | 11.86 | 8.12 |

后两列是同一进程里三套模型轮流推理 300 轮的中位数，背景负载对三者相同。关掉内存池后每次推理都向系统要新内存，掌心检测约缺页 1000 次、关键点约 1150 次，推理慢 8～12%。

## 试过但未采用

- 单线程推理：单核少 15～20 个点，但每帧慢 4～5ms，单手 p95 近 30ms，接近 33ms 的帧间隔。
- 完全关闭工作线程忙等：差别在本机噪声以内。
- 关掉内存池：见上表。
- 关闭权重预打包（`session.disable_prepacking`）：只少约 7 MB，可能拖慢卷积。
- 暂停时关闭摄像头：可省下摄像头采集的 CPU，但恢复时要重新打开摄像头，本轮未做。

## 复测

```powershell
go run ./cmd/perfcheck -frames 300
# 旧找手间隔
go run ./cmd/perfcheck -frames 300 -detect 66ms -idle 120ms
```

原始输出在本机 `tmp/perf-*.log`，不入库。
