# Windows 无接触手势控制系统
## 技术设计方案 V1.2

**目标平台：** Windows 10 / 11  
**开发语言：** C++20  
**运行方式：** 本地后台常驻  
**核心功能：** 手势鼠标、左右键、页面滚动、可视化窗口切换  
**设计重点：** 识别准确率、交互灵敏度、响应延迟、资源占用及操作舒适度

---

## 1. 项目目标

开发一款通过普通摄像头识别手部动作的 Windows 桌面控制程序，让用户无需接触物理鼠标和键盘，即可完成常见桌面操作。

系统直接控制 Windows 原有的鼠标指针，通过系统 API 注入鼠标和窗口控制事件，无需安装虚拟鼠标驱动。

### 1.1 功能要求

- 识别左手、右手及其对应手势。
- 左手食指控制鼠标移动。
- 左手两指执行左键点击。
- 右手两指执行右键点击。
- 三指上下移动控制页面滚动。
- 五指张开唤出 Windows 窗口切换界面。
- 手掌左右滑动选择窗口，撤手后自动确认。
- 握拳停止当前手的操作。
- 支持普通 Windows 桌面应用、浏览器、IDE 等场景。

### 1.2 非功能要求

1. 鼠标移动平稳，尽可能避免抖动。
2. 点击具备防误触机制，不因手势保持而连续点击。
3. 手势之间能够自然切换，不发生明显冲突。
4. 允许小范围手部活动，避免持续抬高手臂。
5. 后台运行时 CPU 和内存占用可控。
6. 无须联网，不保存摄像头视频。
7. 摄像头异常或识别失败时，不执行不确定的操作。

## 2. 手势交互设计

| 手势 | 功能 | 触发方式 |
|---|---|---|
| 左手1指 | 移动鼠标 | 实时跟踪食指位置 |
| 左手2指 | 左键点击 | 进入稳定的两指状态后触发一次 |
| 右手2指 | 右键点击 | 进入稳定的两指状态后触发一次 |
| 任意手3指 | 页面滚动 | 进入滚动模式后，根据上下位移滚动 |
| 任意手5指 | 窗口切换 | 稳定张开五指后弹出切换界面 |
| 五指模式下左右滑动 | 选择窗口 | 根据手掌累计水平位移改变选中项 |
| 五指模式下撤手 | 确认窗口 | 手掌离开识别区域后自动确认 |
| 握拳 | 停止当前手操作 | 立即停止该手产生新的输入事件 |
| 双手离开 | 空闲 | 停止鼠标移动、点击及滚动 |

所有持续性操作均采用状态控制，不允许每帧直接产生一次点击或切屏。

左右手分别维护追踪状态。五指切屏属于独占模式，进入后暂停普通鼠标事件。

## 3. 整体技术架构

系统采用六层结构：

**第一层：视频采集**

- 通过 Windows Media Foundation 获取摄像头画面。
- 默认640×480分辨率、30 FPS。
- 采用最新帧缓冲机制，避免视频帧积压。

**第二层：手部识别**

- 使用 MediaPipe Hand Landmarker。
- 最多同时识别两只手。
- 获取每只手的21个关键点、左右手分类结果。
- 利用连续帧追踪减少重复检测。

**第三层：手势识别与准确性优化**

- 手指伸展状态判断。
- 手掌方向与姿态判断。
- 左右手身份连续追踪。
- 时间滤波与置信度判断。
- 手势稳定性检测。

**第四层：动作控制**

- 鼠标相对位移映射。
- 动态灵敏度控制。
- One Euro Filter 坐标平滑。
- 鼠标点击状态机。
- 滚动手势状态机。
- 五指窗口切换状态机。

**第五层：Windows 系统交互**

- `SetCursorPos()`：鼠标定位。
- `GetCursorPos()`：读取当前鼠标位置。
- `SendInput()`：模拟点击、滚轮和窗口切换输入。
- Windows 原生 Alt + Tab：可视化窗口切换。

**第六层：后台管理**

- 运行状态管理。
- 动态推理频率调节。
- 识别参数配置。
- 摄像头设备管理。
- 异常恢复和资源监控。

数据流程：

摄像头 → 手部关键点 → 手势特征 → 时间滤波 → 状态机 → 动作算法 → Windows API → 系统操作。

## 4. 手势识别准确率优化

这是整个项目最重要的技术模块。

### 4.1 不直接依赖手指数量

单纯判断伸出了几根手指容易产生误识别。

例如：

- 从1指变成3指时，可能短暂经过2指状态。
- 手掌旋转可能导致部分手指被遮挡。
- 弯曲手指可能被错误判断为伸直。
- 双手交叉时可能混淆左右手。

因此应根据21个关键点计算每根手指的伸展状态。

主要判断依据包括：

- 指尖与指根的相对距离。
- 手指关节角度。
- 手掌朝向。
- 指尖相对掌心的位置。
- 相邻手指之间的距离。

使用手掌尺寸对部分距离进行归一化，减少手部离摄像头远近变化带来的影响。

拇指与其余四指采用不同的伸展判断规则。

最终输出的不应只是手指数量，还应包括具体手指组合及手势可信度。

### 4.2 双手身份追踪

MediaPipe 会给出左右手分类结果，但不能仅凭单帧结果决定左键或右键。

系统需要结合：

- 上一帧的手掌位置。
- 当前帧的手掌位置。
- 手部运动轨迹。
- 左右手分类结果。
- 手部特征和匹配置信度。

维持每只手的身份连续性。

当两只手交叉、遮挡或识别结果不确定时，暂停高风险操作，等待追踪恢复。

### 4.3 时间滤波

**目的：过滤短暂识别错误，避免误触发。**

例如，摄像头连续识别到：

1指 → 1指 → 2指 → 1指 → 1指

其中单帧出现的2指可能只是识别噪声。

系统不能立刻执行左键。

建议使用：

**基于时间窗口的多数投票 + 手势进入/退出迟滞机制。**

主要规则：

1. 记录最近约100～200毫秒的手势结果。
2. 统计各手势在窗口内的持续时间。
3. 只有达到稳定条件的手势才允许激活。
4. 已确认的手势不因短暂单帧变化立即退出。
5. 不同功能使用不同的确认时间。

所有时间判断基于单调时钟时间戳，而不是固定帧数，以适应帧率波动。

### 4.4 防误触状态机

以左键点击为例：

- 初始状态为 `CURSOR`，左手一指控制鼠标。
- 检测到两指后进入 `CLICK_CANDIDATE`。
- 判断两指是否稳定维持指定时间。
- 若确认有效，冻结当前光标位置。
- 发送一次鼠标左键事件。
- 进入 `CLICK_LOCKED`，保持两指不会重复点击。
- 两指手势释放后才能再次触发。

如果候选期间识别到了三指，则取消点击候选，转入滚动模式候选。

右键采用相同的边缘触发机制，但由右手独立控制。

## 5. 鼠标移动精度与灵敏度优化

### 5.1 相对位移映射

鼠标不采用简单的摄像头坐标到屏幕坐标的绝对映射。

改用相对位移：

1. 获取当前食指位置。
2. 计算食指相对上一有效帧的位移。
3. 根据手掌尺寸进行适当归一化。
4. 将手指位移乘以当前灵敏度系数。
5. 计算系统鼠标新的坐标。
6. 调用 `SetCursorPos()` 更新光标。

这样用户无需将手移动到摄像头画面边缘，也能控制整个屏幕。

手势状态发生切换时，重新设置位置基准，避免重新进入鼠标模式后光标突然跳跃。

### 5.2 动态灵敏度

**目标：移动距离大时速度快，精确点击时移动慢。**

采用基于移动速度的动态增益。

例如：

| 手指移动状态 | 鼠标控制策略 |
|---|---|
| 几乎静止 | 抑制微小噪声，避免指针抖动 |
| 缓慢移动 | 低灵敏度，适合精确定位 |
| 正常移动 | 标准灵敏度 |
| 快速移动 | 提高灵敏度，实现跨屏移动 |
| 停止移动 | 光标快速稳定 |

计算方式：

鼠标位移 = 手指位移 × 动态灵敏度系数。

动态灵敏度由手指移动速度决定。

建议采用平滑变化的增益曲线，避免速度跨过某个阈值时，鼠标突然加速。

### 5.3 One Euro Filter 自适应平滑

使用 One Euro Filter 对食指坐标进行平滑处理。

传统固定强度的低通滤波存在两个问题：

- 滤波过强，鼠标移动迟缓。
- 滤波过弱，鼠标容易抖动。

One Euro Filter 根据运动速度动态调整滤波强度：

- 手指移动缓慢时，加强平滑，减少抖动。
- 手指移动快速时，减少平滑带来的延迟。

核心参数：

| 参数 | 作用 |
|---|---|
| `min_cutoff` | 决定低速运动时的平滑程度 |
| `beta` | 决定滤波强度随运动速度变化的幅度 |
| `d_cutoff` | 控制速度估计的平滑程度 |

建议先以 `min_cutoff = 1.0 Hz`、`d_cutoff = 1.0 Hz` 为调试起点，`beta` 根据归一化坐标和实际采样数据标定。

这些参数不能脱离坐标单位、采样率和实际噪声情况直接确定。

### 5.4 自适应抖动死区

即使手指保持不动，关键点位置也可能在相邻帧之间出现微小变化。

因此加入死区机制：

- 位移低于噪声阈值时，不更新鼠标。
- 位移持续超过阈值时，恢复移动。
- 死区大小根据静止状态下的关键点噪声估计调整。

不能把死区设置得过大，否则会丢失细微移动。

建议将死区判断放在坐标平滑和速度估计之后，并使用累计位移处理，避免小幅但持续的真实运动完全失效。

### 5.5 精细定位

鼠标控制应同时满足两种需求：

- 快速移动到屏幕上较远的位置。
- 缓慢靠近小按钮并准确点击。

建议通过动态增益自动切换粗定位和精细定位。

点击手势进入候选状态后，暂时保持光标位置，避免伸出第二根手指造成鼠标偏移。

第一版不加入额外精细定位手势。

## 6. 三指页面滚动

三指滚动采用独立状态机。

### 6.1 操作流程

1. 识别到稳定三指手势。
2. 进入 `SCROLL` 模式。
3. 记录当前掌心位置。
4. 持续检测掌心纵向位移。
5. 根据位移方向和距离计算滚动量。
6. 通过 `SendInput()` 发送鼠标滚轮事件。
7. 三指手势释放后结束滚动。

### 6.2 滚动平滑

使用以下方法：

- 对掌心位置进行轻量平滑。
- 设置小幅运动死区。
- 根据累计位移生成滚轮事件。
- 允许调整滚动灵敏度。
- 限制异常大位移产生的滚动量。

滚动采用累计位移，不因每帧的微小坐标误差持续滚动。

第一版不加入惯性滚动。手部停止运动后，页面应停止滚动。

## 7. 五指窗口切换

### 7.1 交互流程

五指窗口切换采用 Windows 原生 Alt + Tab 可视化切换器。

具体操作：

1. 检测到五指张开。
2. 手势稳定后唤出窗口切换器。
3. 手掌左右移动，改变窗口高亮选中项。
4. 手掌停止移动时，保持当前选中项。
5. 手掌从摄像头识别区域撤离。
6. 系统确认手掌离开。
7. 自动激活当前选中的窗口。
8. 关闭窗口切换界面。

切屏过程中不允许触发鼠标点击和滚动操作。

### 7.2 手掌滑动算法

使用掌心坐标计算水平位移。

为避免距离变化影响操作，滑动距离根据手掌宽度归一化。

算法要求：

- 累计水平位移超过阈值时，移动一个窗口选中项。
- 继续移动达到下一个阈值时，再移动一项。
- 左右方向变化时，重新计算有效位移。
- 对细小抖动进行过滤。
- 不因手掌停止移动而改变选中项。

通过调整滑动距离阈值控制切屏灵敏度。

### 7.3 撤手确认算法

撤手确认不能简单等同于识别不到五根手指。

进入切屏模式后，系统持续追踪触发操作的那只手。

需要区分：

- 五指变成四指：手仍在，不确认。
- 手掌短暂被遮挡：等待追踪恢复。
- 手掌真正离开识别区域：确认当前窗口。
- 摄像头故障或程序异常：取消切换并恢复系统状态。

正常撤手确认建议采用150～250毫秒的检测窗口。

如果手掌先快速靠近画面边缘，再从边缘消失，可以作为撤离的辅助证据。

普通追踪丢失与摄像头断连必须分别处理。

### 7.4 Windows 原生实现

使用 `SendInput()`：

- 模拟 Alt 按下。
- 模拟 Tab 按下与释放，打开窗口切换器。
- 保持 Alt 按下。
- 右滑时发送 Tab。
- 左滑时发送 Shift + Tab。
- 撤手确认时释放 Alt。

需要保证窗口切换异常退出时释放模拟按键。

为防止程序崩溃造成按键残留，应设置切屏超时，并考虑增加独立的恢复监控机制。

## 8. 手势冲突处理

为了提高操作准确性，整个系统必须统一管理手势状态。

建议优先级：

1. 异常停止或全局暂停。
2. 已进入的窗口切换模式。
3. 已进入的滚动模式。
4. 点击确认过程。
5. 鼠标移动。
6. 空闲。

优先级不意味着在普通鼠标模式下看到任何瞬间五指结果就立即切屏。所有模式都必须满足对应的激活条件。

特别处理以下情况：

| 场景 | 处理策略 |
|---|---|
| 1指变2指 | 暂停光标移动，等待点击确认 |
| 1指快速变3指 | 取消中间两指候选，进入滚动候选 |
| 2指持续保持 | 点击只触发一次 |
| 左右手同时出现 | 分别追踪，根据操作状态决定是否接受输入 |
| 两只手同时发出命令 | 独占模式优先，其余冲突操作暂时忽略 |
| 5指切屏期间出现2指 | 忽略点击手势 |
| 切屏时短暂丢帧 | 保持当前窗口选中状态 |
| 摄像头突然断开 | 停止输入，取消尚未确认的操作 |

## 10. 后台资源优化

### 10.1 性能目标

| 指标 | 设计目标 |
|---|---|
| 常驻内存 | 尽量低于300 MB |
| 日常 CPU 占用 | 平均尽量低于10% |
| 活动推理帧率 | 目标25～30 FPS |
| 空闲识别帧率 | 5～10 FPS，需评估唤醒延迟 |
| 光标端到端延迟 | 争取低于120ms |
| 点击响应 | 争取150～250ms，包含确认时间 |
| 长时间运行 | 连续8小时无明显性能退化 |
| 数据处理 | 完全本地运行 |
| 摄像头视频 | 不保存、不上传 |

上述指标属于开发验收目标，需要在目标电脑上实测，不能直接视为已达到的性能。

### 10.2 优化策略

**动态识别频率**

- 无手状态降低推理频率。
- 检测到手后提高推理频率。
- 鼠标移动阶段优先保证低延迟。
- 切屏模式保证手掌轨迹连续。

**连续帧追踪**

尽量利用上一帧的手部位置，减少完整手掌检测次数。

**异步视频处理**

- 摄像头采集独立运行。
- 模型推理与输入控制分离。
- 缓冲区只保留最新帧。
- 推理延迟过高时丢弃旧帧。

**内存优化**

- 模型仅初始化一次。
- 视频帧使用固定容量缓冲区。
- 不保留历史视频画面。
- 仅保存短时间窗口内的关键点、状态和时间戳。
- 不持续绘制摄像头预览。

**后台运行**

使用普通 Windows 用户态后台进程，支持系统托盘状态显示、暂停、恢复和退出。

不需要 Electron，也不需要持续运行图形预览窗口。

## 11. 准确性验收标准

模型识别率与实际桌面操作成功率分别测试。

### 11.1 模型层面

记录：

- 左右手识别错误率。
- 手指数量和组合识别错误率。
- 手势切换过程中的误分类率。
- 关键点静止抖动程度。
- 手部追踪中断次数。
- 手势识别响应延迟。

测试环境包括不同光照、手掌角度、摄像头距离、双手交叉和低位手势操作。

### 11.2 交互层面

| 项目 | 建议目标 |
|---|---|
| 左键点击成功率 | ≥98% |
| 右键点击成功率 | ≥98% |
| 五指切屏成功率 | ≥99% |
| 撤手确认成功率 | ≥99% |
| 常见按钮定位并点击成功率 | ≥95% |
| 连续30分钟空闲误触发 | 0次 |
| 鼠标静止抖动 | 以实际屏幕像素偏移测量并逐步优化 |
| 连续8小时运行 | 无明显内存增长或输入状态异常 |

这些数值是建议的验收门槛，并不代表现有模型已达到相应指标。

测试至少覆盖多轮、不同使用场景，不能只凭几十次操作判断是否稳定。

尤其需要分别统计：

- 用户做出了手势，但程序没有响应。
- 用户没有做对应手势，但程序错误触发。
- 程序响应正确，但延迟过高。
- 光标移动基本正确，却无法精确点击目标。

误触发率需要按每小时运行时间统计，因为程序将长期在后台运行。

## 15. 技术风险与限制

**鼠标精确操作：** 普通摄像头无法保证达到物理鼠标的定位精度。需要通过动态增益、坐标滤波和实际校准改善，但不承诺完全替代高精度鼠标操作。

**识别误触：** 时间滤波可以降低短暂误识别引发的操作，但会增加响应延迟，需要在准确性和速度之间进行实测优化。

**摄像头视角：** 笔记本内置摄像头可能无法拍到桌面附近的手部区域。必须在实际设备上验证摄像头摆放与身体姿势。

**Windows 权限：** 普通用户态程序无法保证控制管理员权限窗口、UAC 安全桌面等特殊界面。

**原生窗口切换：** Alt + Tab 切换器的显示与可选窗口受系统版本和设置影响，需要在目标 Windows 环境验证。对模拟按键释放失败必须提供恢复处理。

**长时间运行：** 性能优化目标需要通过 CPU 占用、内存占用、延迟与异常率实测确认，不能仅凭技术栈推断。

## 16. 最终设计结论

第一版采用：

**C++20 + MediaPipe Hand Landmarker + Windows Media Foundation + Win32 API。**

识别准确性采用：

**手部关键点几何判断 + 左右手连续追踪 + 时间窗口滤波 + 手势状态机。**

鼠标控制采用：

**相对位移映射 + 动态灵敏度 + One Euro Filter + 自适应抖动死区。**

窗口切换采用：

**五指触发 Windows Alt + Tab → 左右滑动选择 → 撤手自动确认。**

重点验收鼠标定位精度、点击误触率、窗口切换可靠性、响应延迟、资源占用，以及低负担姿势下的实际操作体验。
