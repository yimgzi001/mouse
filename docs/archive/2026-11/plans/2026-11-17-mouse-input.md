# 摄像头到 Windows 鼠标输入

目标：沿用现有 Go 摄像头、ONNX 跟踪器和动作引擎，提供可直接运行的鼠标控制程序。

设计：增加 Windows Injector，使用 GetCursorPos / SetCursorPos 和 SendInput；控制器把关键点识别为手势后交给现有引擎。默认仅启用左手一指移动、左手两指左键、右手两指右键和握拳停止。两指保持只点击一次。命令行提供摄像头选择、灵敏度、诊断模式；F8 暂停恢复、F9/Ctrl+C 退出。所有退出路径先停止输入并释放程序持有的键，再关闭摄像头。视频仅在内存处理。

- [x] 实现 internal/wininput：Windows 原生输入、错误报告、按键状态与退出时释放；验证 INPUT 布局、左右键事件和错误路径。

## 验证记录

- `go test -count=1 ./...`：通过。
- `go test -race -count=1 ./...`：通过（包含最终摄像头关闭超时修复）。
- `go vet ./...`：通过。
- `go build -o bin/mouse.exe ./cmd/mouse`：通过；配套 DLL 放在 `bin/runtime`。
- `go run ./cmd/visioncheck`：10 张图片、15 只手，数量与参考一致；关键点平均偏差 0.38px，最大偏差 1.87px。
- `MOUSE_LIVE_TEST=1 go test -count=1 -run '^TestLiveDesktopPointerAndClicks$' -v ./internal/wininput`（PowerShell 使用环境变量写法）：通过。真实识别控制器把测试窗口中的光标向右移动 30px，窗口收到一次左键和一次右键的按下、释放消息。
- `go run ./cmd/mouse -dry-run -verbose -seconds 5`：XiaoMi USB 2.0 Webcam，640×480/30 FPS，处理 135 帧，约 26.9 FPS。
- 在项目目录之外运行 `bin/mouse.exe -dry-run -verbose -seconds 3`：成功找到打包 DLL、打开摄像头、处理 75 帧并正常退出。

修复的原有引擎问题均先由回归测试复现：旧投票手势误完成点击、未知左右手继续移动、丢手时间计入点击确认。独立代码审查发现同步摄像头读帧可能阻塞退出；新增 `Capture.CloseContext` 和超时测试，主程序在释放输入后最多等待驱动清理 2 秒再退出。正常清理仍会等待资源完整释放；超时后由进程退出回收设备资源。

摄像头诊断期间画面中没有手。原生移动/点击使用真实模型输出的记录样本，真人操作准确率、光照适应、热键手动体验和长时间运行尚未验收。

## 真人试用后的调整

- 用户确认鼠标可以移动和点击，随后将本次运行灵敏度设为 0.5。
- 新增可选原生实时预览：内存中的画面、关键点、左右手与手势状态；暂停时可继续观察识别，停止发送输入；F6 可即时交换左右手标签。左右手校正由实际手与预览标签核对后决定，默认关闭。
- 用户明确选择“左右手一指都能移动”。默认移动绑定改为任意手；双手同时一指时沿用引擎的资源互斥，由先进入者控制，另一只手不抢占。两指点击仍区分左右手。未知左右手不能抢占鼠标，也不能继续移动已有鼠标控制器。
- 新增左右手移动、双手互斥、未知手不阻塞有效手、暂停预览不发送输入的回归测试；`go test -race -count=1 ./...`、`go vet ./...` 及构建通过。原生预览的缓冲复制与窗口关闭测试已在 race 模式通过。
- 已用 `-preview -verbose -sensitivity 0.5` 启动新版本。截图工具两次超时，用户已确认能看到预览并观察手势；实际左右手移动体验待用户继续反馈。
