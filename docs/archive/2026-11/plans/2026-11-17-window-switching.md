# 窗口切换交互调整

用户反馈：五指选窗唤出太慢，握拳应确认停留的窗口；四指并拢、拇指收起左右快挥应直接执行 Alt+Tab 快切。

- 去掉五指投票后的额外等待，仍过滤单帧误识别；握拳释放 Alt 确认，暂停/异常/超时仍 Esc 取消；保留撤手确认兼容行为。
- 四指掌向右挥执行一次 Alt+Tab，向左执行一次 Alt+Shift+Tab，立即松开所有键；先结束拖拽/缩放，选窗模式中不另发快切。
- 默认 250ms 内水平移动约 0.65 掌长判定快挥，回摆冷却 350ms，并由切屏灵敏度倍率调整距离阈值。
- 原始手势变化、短暂丢手后重建轨迹；姿态变化不继承其他未绑定动作的冷却。未知左右手、暂停时不快切。
- 测试包含唤出延迟、握拳确认、单帧防抖、正反快切、回摆、慢速/竖直拒绝、丢手和换姿态保护、拖拽抢占、独占选窗，以及未使用的一指挥动不能抑制后续四指快切。

当前目录没有 Git 元数据，不初始化或提交仓库。其他手势及用户独立灵敏度保存保持原有逻辑。

## 右手摆动不跟随修复

- 真人日志 16:55:04 右手五指启动选窗后，16:55:05～12 连续识别为四指，拇指开放度约 0.2～0.5；原引擎仍要求原始和稳定姿势每帧都为五指，导致反复重建轨迹、无法选窗。这是手指分类门槛造成的停跟，左右手选窗参数实际相同。
- 选窗启动后跟随所属手的掌心，允许手指分类改变；握拳先确认，未知左右手/丢手仍冻结，其他手势与另一只手不抢占。
- 五指改为至少两次连续观察、跨度至少 30ms 的独立确认，替代通用多数投票；单帧、换姿态、丢手和过长采样间隔均不能复用之前的候选。
- 新增先失败的测试复现四/五指跳变停跟、从旧姿态切到五指需等待投票的问题，随后验证左右手同轨迹一致、双向选择及确认与输入释放。原先“四指不动”的用例改为手掌坐标不变，避免把回原点的位移错误当成静止。
- 保留全部用户已保存的灵敏度。本轮识别门槛不代表真人端到端延迟保证，最终体验仍需摄像头试用。
- 本轮验证：`go test -race -count=1 ./...`、`go vet ./...`、`go build -o bin/mouse-palm-follow.exe ./cmd/mouse` 全部通过，独立只读审查未发现重要问题。正常关闭旧预览后替换并启动 `bin/mouse.exe -preview -verbose`，诊断日志为 `tmp/mouse-palm-follow.log`。
