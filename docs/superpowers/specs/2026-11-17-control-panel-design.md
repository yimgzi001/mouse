# 原生配置面板与手势动作解耦设计（已确认）

> 本文保留本轮已批准的设计范围及取舍，“现状”描述实施前背景。方案已实现；现行模块与配置约束见[当前架构](../../architecture.md)，交付证据与未完成验收见[验收记录](../../native-panel-validation-2026-11-17.md)。

## 现状与目标

用户指出项目还包含配置面板和手势、动作解耦。此前通过真人测试的是现有摄像头输入链路，不代表整个产品完成。

现有代码已经有 `engine.Binding`、动作参数目录、触发方式目录和参数校验，但 `control.NewWithPreferences` / `SetPreferences` 仍调用 `bindingsFor(p)`，实际运行映射不能由用户保存和编辑。现有原生预览只提供六个灵敏度滑块；双食指缩放直接由引擎单独识别执行；选窗确认和按键释放保护仍含手势名称判断。上述部分均在本次范围内。

目标是让用户在面板中修改“哪只手、什么手势、何时触发、执行什么动作及参数”，保存后立即生效，重启保留，不再通过修改 Go 代码换映射。保持已验收的默认操作和独立灵敏度。

## 方案比较与建议

- 本地网页面板：Go 标准库提供页面和接口，浏览器显示；适合编辑绑定表、动态动作参数、导入导出和冲突提示，可以复用现有引擎元数据，无新增前端构建运行时。
- 扩展现有原生 Win32 控件：沿用单窗口，但动态表单、配置编辑和导入导出需要大量低层控件工作，后续扩展成本更高。
- 引入桌面 WebView 框架：可将网页放进桌面窗口，但当前项目没有相应依赖、运行时检测和打包基础，增加本轮工作。

用户确认改用 Windows 原生窗口，保留其余配置与解耦范围。采用现有 Go + Win32 控件，不引入浏览器服务、WebView 或前端依赖。原生配置窗口与实时预览分开，面板提供预览显示/隐藏入口。

## 面板内容

```text
手势鼠标                         [暂停 / 恢复] [实时预览] [退出]
运行状态：摄像头 / 处理帧率 / 当前左右手手势 / 最近动作

手势绑定 | 灵敏度与识别 | 配置管理

启用  名称          手别    手势       触发方式    动作       参数
 ✓   左拳单击      左手    握拳       做出一次    鼠标单击   左键
 ✓   左中指 Tab    左手    只伸中指   做出一次    按键       Tab
 ✓   右中指回车    右手    只伸中指   做出一次    按键       Enter
 ✓   右手 OK       右手    OK         做出一次    按键       右 Alt
 ✓   双食指缩放    双手    双食指     保持        缩放       倍率

[新增绑定]                    [撤销未保存修改] [保存并应用]
```

- 绑定可新增、删除、启停、修改名称、手别、手势、触发方式、确认时间、重复间隔及动作参数。参数根据动作目录动态展示，例如鼠标键、键盘组合、移动倍率、滚动方向。
- 内置手势库提供名称、说明、手指示意和可用手别；首版编辑已有手势到动作的映射，不新增摄像头几何手势编辑器或训练模型。
- 动作库优先展示鼠标、键盘、切窗、暂停/停止。已移除的媒体动作不默认重新绑定；不得因迁移恢复用户弃用的映射。打开外部程序等动作仍遵循现有引擎能力开关。
- 双手组合手势只展示兼容动作和触发方式；双食指可绑定距离缩放，也可绑定一次性按键/点击，不能伪装成单手指针或拖拽来源。
- 灵敏度沿用六个独立值；识别页可调确认时间、丢手宽限等已有参数，显示合法范围。调整后继续保持原暂停状态。
- 配置管理包含本地 JSON 导出、导入校验和恢复默认；导入和恢复先进入草稿，用户按“保存并应用”才影响运行。恢复默认映射与恢复灵敏度分开，避免覆盖已调好的倍率。
- 当前运行配置和未保存草稿分开；离开页面有未保存状态提示。错误指出对应行和字段，不显示内部堆栈。
- 打开面板编辑不自动发送输入；提供明显的暂停按钮。关闭面板隐藏到后台、保留草稿，F7 可重新显示；退出按钮和 F9 正常释放输入并退出。原生预览的显示/隐藏由面板控制，不因关闭预览而意外退出后台。仅单独运行预览、不启用面板时保留旧的关闭即退出行为。

## 解耦边界

1. **识别层**：只根据手部关键点、识别参数和启用的手势定义产生手势状态、变化、方向、坐标等数据，不调用 Windows 输入。识别规则的匹配优先级不随动作绑定启停改变，避免禁用一个动作后该姿势落入握拳或五指并触发别的操作。
2. **组合手势层**：双食指等组合手势产生独立事件和距离数据，本身不发 Ctrl/滚轮，也不直接决定是否冻结指针。
3. **绑定层**：将手别、手势和触发方式连接到动作。通过动作能力检查兼容性；匹配的双手组合绑定优先于单手操作，确认期间的资源占用按绑定声明处理。没有启用组合绑定时不抢占正常移动。
4. **动作层**：单击、移动、拖拽、缩放、切窗、单键等只接收对应数据并执行。切窗确认/取消由明确的动作类型表达，不能再在动作中以 `rawPose == "fist"` 决定用户意图；快挥也由绑定路由，不限于固定的切窗动作。
5. **状态保护**：保持一次性动作不重复，未知手/短暂丢手冻结和确认重计；配置切换、暂停、退出释放持有输入。已验收的“按键收拳不误点”和“切屏中保持的点击/Tab 不在新窗口补发”保留，规则依据动作类别与释放事件，不固定中指、OK、拳等名字。

首版默认识别集合固定为当前运行使用的 `fist`、`point`、`two`、`middle`、`click_pinch`、`three`、`four`、`five`、`ok`、`thumb_out`，不从绑定列表推导。`point_up` 等方向细分、`five_back` 等重叠变体和实验手势不默认启用，避免抢走一指/五指的识别结果。首版手势库展示并绑定这个明确集合及双食指；新增几何手势和重叠规则编辑留到后续，不能用“启停动作”间接改变这个识别集合。

首版“启用/停用”指绑定是否执行，不从分类器删除手势；识别仍能显示禁用动作对应的姿势，不回落为其他手势。版本化配置中记录默认识别集合，以便未来迁移，但首版面板不开放低层识别规则启停或优先级编辑。

双手组合绑定确认期间及有效保持期间占用两手，暂停单手移动和其他冲突动作；一次性动作触发后仍等组合姿势释放再让出控制，防止保持双食指时又移动指针。组合结束后重新建立单手位移基准。组合绑定禁用时不进入组合确认或占用状态。

### 按键释放保护的明确规则

释放保护是绑定中的可配置数据，不在引擎中判断特定手势名。每条一次性按键绑定可声明“返回哪些手势时只算释放、不执行新动作”；默认仅给左中指 Tab 声明返回握拳时的保护，保留已验收操作。面板在高级设置中提供手势多选和开关，不让用户填写内部 ID。

- 绑定 A 发出按键后，若接下来进入它声明的返回姿势 B，该次 B 不触发点击，直到稳定离开 B 或手彻底撤离后重新出现。短暂丢手、未知手和原始识别抖动不能解除保护。
- 若先稳定进入未列出的姿势 C，A 的释放保护结束，C 可正常执行；之后做 B 也按正常绑定执行。
- 若用户明确需要 A→B 直接执行 B，可以移除该返回姿势或关闭保护。不能按所有键盘动作→所有点击动作一刀切地抑制。
- 选窗期间另一只手的手势被消耗是独立的资源占用保护，持续到其姿势释放，不能由上述释放保护开关绕过。

### 全局灵敏度与动作倍率

六个现有灵敏度是全局基础倍率；每条连续动作绑定的“动作倍率”是额外相对倍率，默认 1。两者相乘，例如左手基础 0.5、该移动绑定倍率 2，实际为 1；面板显示计算后的值。迁移默认绑定时将原来直接写入绑定的左/右移动和拖拽倍率提取为基础值，绑定本身设为 1，不能重复相乘。

- 移动根据实际手别选择左手/右手基础倍率；“任意手”绑定也按当前识别手别计算，未知手不移动。
- 拖拽、滚动、切屏和距离缩放分别乘各自的全局基础倍率，不再叠乘左右手移动倍率。
- 新增绑定或修改手别不复制基础值进绑定，不修改全局滑块；同一基础滑块的变化作用于对应类别的所有绑定。
- 单键、单击等离散动作不展示灵敏度。所有存储输入先检查有限值与合法范围，实际计算保留现有动作的位移/单帧输出保护。

首版不扩展自定义模型、任意组合手势编程、云同步或安装包；配置面板与运行绑定链路必须完成，不能只交付能编辑但不驱动实际输入的界面。

## 配置存储与迁移

- 统一的版本化配置包含：现有 Preferences、识别参数、固定基础识别集合、绑定列表及各绑定启停状态。继续使用当前 `-config` 路径，默认 EXE 同目录 `settings.json`。
- 自动读取旧的七字段设置文件，保留全部已调值，补入当前已验收映射；写新格式前留原文件备份。缺失配置使用默认；明确空绑定列表代表禁用所有绑定，不能静默恢复默认。
- 所有写入口（面板、原生预览滑块、F6）通过同一配置服务更新完整快照，避免调灵敏度时覆盖绑定。配置返回修订号，过期草稿保存拒绝并提示重新载入，不能覆盖另一入口刚保存的值。
- 保存流程：完整解析及校验 → 准备新运行快照 → 原子落盘 → 释放旧运行输入并切换快照；无效配置不写入、不改变当前运行。磁盘失败保留原配置和运行状态，明确返回失败。
- 校验包括：未知手势/动作/按键、重复 ID、参数非有限值或越界、手别/动作不兼容、连续动作使用错误触发方式、冲突绑定、配置版本不支持。针对单手同一手势及触发的重复动作明确报冲突；“任意手”与具体手覆盖按现有具体手优先规则展示说明。

## 原生窗口接口和实时状态

- 窗口通过 Go 回调读取能力目录、读取/应用带修订号的配置、暂停/恢复、显示/隐藏预览及退出；没有 HTTP 接口。
- 通过窗口定时消息更新当前手势、动作、运行状态和统计。实时图像只在原生预览里显示，不新增视频编码或传输。
- 打开和保存配置使用 Windows 文件对话框，文件大小限制 1MiB；导入只更新草稿。导出当前草稿前校验，不替换正在使用的运行配置。
- 面板隐藏后仍保持后台输入，状态绘制停止；保留草稿与稳定的修订号，重复显示不重建模型。

## 验收

- 从面板将左中指 Tab 改为其他单键，实际输入随之改变，重启后仍生效；禁用后无该动作，识别仍显示中指。
- 动作参数、左右手、触发方式改变后分别验证；错误组合拒绝，现有配置保持运行。
- 双食指绑定可禁用，禁用后不缩放也不抢单手指针；重新绑定缩放及一次性按键验证，不保留缩放专用的固定入口。
- 修改设置时正在拖拽或选窗，确认按钮/Alt 被释放，暂停状态不自动恢复；切换后旧姿势不在新窗口重复点击或补发键盘事件。
- 旧配置迁移保留当前六项倍率和左右手校正；F6、面板保存、原生预览滑块不会互相覆盖配置；显式空绑定、导入错误、写盘错误均有验证。
- 面板完成新增/编辑/启停/删除/导出/导入/恢复默认的真实交互测试，默认映射回归测试通过。
- 运行 `go test -race -count=1 ./...`、`go vet ./...`、构建和参考图片识别校验；对比面板空闲开/关时的性能，不能重新引入模型忙等或持续视频编码。

## 实现涉及位置

- `internal/control`：配置快照、迁移、保存/应用服务、识别/组合事件与动作路由连接；默认绑定仅作为初始预设。
- `internal/gesture`：独立于绑定启停的手势目录和匹配事件。
- `internal/engine`：动作能力元数据、可配置双手动作、确认/取消动作、通用触发和状态保护。
- `internal/panel`（新增）：原生窗口、绑定编辑器、动态参数、识别/灵敏度设置与文件导入导出。
- `internal/preview`：显示/隐藏入口、配置来源统一，保留现有图像显示。
- `cmd/mouse`：统一初始化、持久化入口、面板和生命周期连接。

独立构建审查提出的识别集合、释放保护、倍率计算、组合占用四项边界已在上文明确。2026-11-17，用户选择 Windows 原生窗口，按该选择落实本设计。当时工作目录尚无 Git 元数据，实现阶段保留原有文件，没有自行初始化仓库；这不限制用户后续明确要求建立仓库。
