# 识别修复记录（2026-11-17）

本轮按用户反馈修正识别稳定性：以后三指取代 OK、放慢五指唤出、延长丢手宽限，新增新手观察、最小掌宽、左右手锁定和重复手合并，并提高进程优先级。下列结果来自自动化测试和固定图片回放，尚未经真人试用。当前操作以[项目使用说明](../README.md)为准，配置约束见[当前架构与配置](architecture.md)。

## 行为变化

| 项目 | 之前 | 现在 |
|---|---|---|
| 右 Alt 手势 | 右手 OK（拇指食指相碰，其余三指伸直） | 右手后三指（中指、无名指、小指伸直，食指收起，拇指随意），确认时间仍为 80ms |
| 五指唤出选窗 | 连续确认 30ms | 150ms；从其他手势直接换成五指时至少 300ms |
| 丢手宽限 | 200ms | 400ms；期间在附近重新出现的手保持原状态 |
| 新出现的手 | 立即可触发任何动作 | 前 200ms 只移动指针 |
| 远处的小手 | 同样跟踪 | 掌宽（手腕到中指根）不足 45 像素的新手不跟踪 |
| 已跟踪的手 | 关键点置信度低于 0.6 即丢失 | 低于 0.5 才丢失，转动或快速移动时更稳 |
| 左右手标签 | 越过翻转阈值即翻转 | 稳定 500ms 后锁定，需连续 700ms 的相反判断才翻转 |
| 同一只手的重复检测 | 只按框重叠判断，偶尔占两个跟踪位 | 框重叠或掌心距离小于 0.6 掌长即合并 |
| 跟踪单手时找第二只手 | 每 200ms 一次 | 每 66ms 一次 |
| 进程优先级 | 正常 | 高于正常，并关闭 Windows 节能降频；设置失败只记日志 |

新手观察时间、最小掌宽、丢手宽限、五指和后三指确认时间可在面板“高级 · 识别”页修改；300ms 五指切换下限、左右手锁定和重复手合并为固定参数。

## 配置升级

配置版本由 2 升为 3。读取版本 2 时自动升级：`ok` 改为 `middle_ring_pinky`，默认绑定“右手 OK 右 Alt”改名为“右手后三指 右 Alt”，`okConfirmMs` 的值转入 `middleRingPinkyConfirmMs`；仍为旧默认值的五指 30ms、丢手 200ms 换成新默认，用户改过的值保留。新程序启动时即写回版本 3，原文件备份为 `settings.json.v2.bak`，已有备份不覆盖。本机升级前另存了 `bin/settings.json.before-phase1.bak`。

旧程序读不了版本 3 配置。回退时先退出新程序，再把 `settings.json.v2.bak` 或 `settings.json.before-phase1.bak` 复制回 `settings.json`。

## 图片回放 CPU 对比

用初始提交 `f2407b5` 和本轮代码分别构建 `cmd/perfcheck`，参数 `-frames 180 -threads 2 -spin run`，不开摄像头，按旧新、旧新、新旧、旧新的顺序各运行 4 轮，期间不运行其他摄像头程序或构建。测试图片与[性能检查记录](performance-2026-11-17.md)相同。含超出 30 FPS 帧预算帧的轮次剔除，其中本轮代码第 1 轮受明显干扰（单手 59 帧、双手 130 帧超预算）；下表为其余轮次平均，保留轮次均约 30 FPS。

| 场景 | 上一版 CPU | 本轮 CPU | 上一版平均 / p95 | 本轮平均 / p95 | 掌心检测次数 |
|---|---:|---:|---:|---:|---:|
| 无手 | 1.15% | 1.27% | 3.18 / 13.69 ms | 3.38 / 14.48 ms | 45 → 45 |
| 单手 | 3.54% | 4.71% | 10.31 / 22.60 ms | 13.69 / 23.21 ms | 28 → 82 |
| 双手 | 5.75% | 5.66% | 17.16 / 22.40 ms | 17.23 / 20.35 ms | 0 → 0 |

无手、双手与上一版持平。单手整机 CPU 高约 1.2 个百分点、平均每帧多约 3.4ms，p95 基本不变：跟踪单手时找第二只手的间隔从 200ms 缩短为 66ms，180 帧内掌心检测从 28 次增至 82 次，换来第二只手进入画面后更快被接收。CPU 为整机归一化占用。原始输出在本机 `tmp/perf-ab-*.jsonl`，不入库。
